# Cybernetic System

Публичный репозиторий пакета мода Arma 3 `[FOD] Cybernetics System`.

## Содержимое

- `addons/PHEN_Cybernetics.pbo` - собранный PBO аддона.
- `source/PHEN_Cybernetics/` - исходное содержимое аддона для проверки и правок.
- `mod.cpp`, `meta.cpp`, `PHEN_CS_icon_*.paa` - метаданные мода и иконки.
- `tests/*.ps1` - статические проверки исходников и поставляемого PBO.

## Текущее состояние сборки

В публичный пакет включены локализованные CBA-настройки, фильтр списка имплантов Ripperdoc и глазной имплант `Argus Combat Optics Mk.IV`.

## Глазной имплант Argus Combat Optics Mk.IV

Имплант находится в категории `OCULAR` и имеет ID:

```sqf
"PHEN_CS_Cybernetic_OCULAR_ITEM_3"
```

Функционал импланта:

- распознавание и 3D-обозначение мин в радиусе 50 метров;
- подсветка союзной пехоты, техники, авиации, БПЛА и стационарных установок до 1000 метров;
- мини-радар видимых союзных контактов с переключаемым масштабом;
- собственная телеметрия игрока: пульс, давление, кровь, кислород;
- ночное видение и тепловизионный режим через `PHEN_CS_LowLightOptics_MkIV`;
- live-маркер приблизительной точки попадания до выстрела для поддерживаемого текущего оружия;
- CBA-настройки размера HUD, 3D-меток союзников и 3D-меток мин для каждого локального игрока отдельно.

## Правила видимости Argus

Контакты ближе 10 метров отображаются по радиусу, без угловой проверки. Это сделано для ближнего сенсорного предупреждения, включая мины.

На дистанции от 10 до 100 метров используется широкий конус обзора 110 градусов. Контакт должен находиться в этом конусе и проходить проверку видимости.

Дальше 100 метров используется более строгий передний конус. Логика видимости считается от юнита с имплантом через направление его взгляда, а не от активной render-камеры, Zeus-камеры или scripted camera. Это важно: наблюдатель в Zeus не должен заставлять Argus видеть цели за спиной игрока.

Мини-радар Argus использует тот же видимый кэш контактов, что и 3D-метки. Он не должен показывать союзников за спиной, если они уже отфильтрованы системой видимости. Исключение - ближняя зона 10 метров, где контакты показываются по радиусу.

## Маркер точки попадания

Маркер строится до выстрела. Он не читает фактическое место попадания уже выпущенной пули.

Расчет использует:

- `weaponState` текущего юнита;
- текущее оружие, muzzle, fire mode и магазин;
- `currentZeroing [_weapon, _muzzle]`;
- направление оружия через `weaponDirection`;
- `initSpeed` из `CfgMagazines`, `CfgWeapons` / muzzle / mode и `CfgAmmo`;
- `airFriction`, `coefGravity`, `timeToLive`, `simulationStep` и `artilleryLock` из `CfgAmmo`;
- трассировку траектории через `lineIntersectsSurfaces` по `FIRE` с fallback `GEOM`.

Если Arma уже отдает фактическое направление ствола через `weaponDirection`, Argus не накладывает дополнительную искусственную поправку пристрелки поверх этого направления. Это снижает расхождение метки и убирает дрейф от движения камеры, когда ствол фактически не меняет направление.

Argus уверенно считает только поддерживаемую bullet/shell-подобную баллистику. Для launcher/rocket/missile/grenade-симуляций мод не рисует ложную "точную" точку попадания под игроком или рядом с ним. Если solver не может получить валидную поверхность дальше минимальной безопасной дистанции, решение сбрасывается вместо показа неправильной метки.

При включенном ACE Advanced Ballistics маркер остается приблизительным и помечается `APPROX ACE`. В коде не используется внутренний undocumented solver ACE. Argus использует только доступные config-параметры Arma/ACE и не делает вид, что может заранее получить закрытое движковое решение для каждого боеприпаса.

## Фокусировка взгляда Argus

Argus больше не использует scripted camera для увеличения. В runtime удалены `camCreate`, `cameraEffect ["Internal","Back"]` и `camSetFov` из боевой фокусировки, потому что такая схема переключает изображение игрока на отдельную камеру и ломает управление телом, стрельбу, поворот головы и направление взгляда.

Вместо этого Argus работает со штатной фокусировкой Arma 3 через input action `zoomTemp`. Это та же логика, которую игрок обычно использует своей назначенной клавишей фокусировки взгляда. Мод может читать состояние этой action через `inputAction "zoomTemp"` и показывать привязанные клавиши через `actionKeysNamesArray "zoomTemp"`, но не подменяет камеру игрока.

Важно: скриптовый runtime SQF не дает надежного способа усилить штатную фокусировку взгляда так, чтобы это выглядело как настоящая движковая фокусировка и одновременно не переключало игрока в scripted camera. Если нужен более сильный native focus zoom, это нужно делать отдельным config-level patch для FOV персонажа и проверять совместимость с модсетом. В текущем пакете выбран безопасный вариант: сохранить штатную фокусировку Arma и не ломать управление.

## Управление Argus в CBA

Клавиши находятся в категории:

```text
[FOD] Cybernetics System - Tactical HUD
```

Доступные действия:

```text
Cycle Argus Radar Scale
Show Argus Native Focus Status
```

`Cycle Argus Radar Scale` переключает масштаб мини-радара: 250, 500, 1000 и 2000 метров. Начальный масштаб - 1000 метров.

`Show Argus Native Focus Status` показывает состояние штатной Arma-фокусировки и текущие клавиши, назначенные игроком на `zoomTemp`. Оно не включает отдельную камеру и не переключает оружие.

## Масштаб интерфейса Argus

В CBA Addon Options добавлены локальные настройки. Они действуют только для конкретного игрока:

```text
Argus HUD Scale
Argus Allied Marker Scale
Argus Mine Marker Scale
```

`Argus HUD Scale` меняет размер панели Combat Sensor и мини-радара. Текст масштабируется мягче, чем панель, чтобы на максимальном размере не выходить за пределы видимой области.

`Argus Allied Marker Scale` меняет размер 3D-иконок и текста над союзной пехотой, техникой, БПЛА, авиацией и стационарными установками.

`Argus Mine Marker Scale` отдельно меняет размер 3D-иконок и текста мин.

Значение `1.00` сохраняет размер по умолчанию. Настройки локальные, поэтому каждый игрок может подобрать масштаб под свой монитор и интерфейс.

```sqf
    "PHEN_CS_Cybernetic_OCULAR_ITEM_3"
], true];
```

## Ripperdoc whitelist и blacklist

Фильтр Ripperdoc можно настраивать через init-поле логики модуля Ripperdoc или через init синхронизированного объекта Ripperdoc.

Фильтр ожидает массив строк. По возможности используйте стабильные внутренние ID киберимплантов. Отображаемые названия тоже принимаются, но ID безопаснее, потому что отображаемые названия могут меняться настройками.

Пример whitelist:

```sqf
this setVariable ["PHEN_CS_RipperdocAllowedList", [
    "PHEN_CS_Cybernetic_ARMS_ITEM_0",
    "PHEN_CS_Cybernetic_LEGS_ITEM_3"
], true];
```

Пример blacklist:

```sqf
this setVariable ["PHEN_CS_RipperdocDeniedList", [
    "PHEN_CS_Cybernetic_OPERATINGSYSTEM_ITEM_2",
    "PHEN_CS_Cybernetic_LEGS_ITEM_7"
], true];
```

Пример явного режима:

```sqf
this setVariable ["PHEN_CS_RipperdocFilterMode", "whitelist", true];
```

Поддерживаемые значения режима:

- `"whitelist"` - показывать только разрешенный список;
- `"blacklist"` - скрывать запрещенный список;
- `"both"` - сначала применить whitelist, затем убрать blacklist;
- `"off"` - отключить фильтр.

Если режим не указан, мод сам выбирает поведение:

- есть whitelist - работает как whitelist;
- whitelist нет, но есть blacklist - работает как blacklist;
- есть оба списка - работает как both.
